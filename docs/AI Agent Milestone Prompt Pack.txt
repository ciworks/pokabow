# AI Agent Milestone Prompt Pack

Use this document to scaffold the Godot 4.6 game through a separate agentic development tool. Run the prompts in order and start a new agent task for each milestone.

## Required project documents

Before using the prompts, place these files in the local project:

```text
AGENTS.md
docs/GAME_SPEC.md
docs/PHASE-1-IMPLEMENTATION-PLAN.md
docs/decisions/ADR-001-poker-hand-formation-and-scoring.md
docs/decisions/ADR-002-edge-cluster-definition-and-bonus.md
docs/decisions/ADR-003-turn-rules-and-game-end.md
docs/decisions/ADR-004-tile-distribution-and-generation.md
docs/decisions/ADR-005-ai-evaluation-and-search.md
docs/decisions/ADR-006-board-placement-rules.md
docs/decisions/ADR-007-incremental-scoring-architecture.md
docs/decisions/ADR-008-godot-project-architecture.md
```

## Workflow

1. Give the agent only one milestone prompt at a time.
2. Review its proposed changes before allowing implementation if the tool supports approval gates.
3. Require the agent to run tests and report the exact commands and results.
4. Open the project in Godot and manually verify the milestone.
5. Fix failures before proceeding.
6. Commit the completed milestone to version control.
7. Start the next prompt only after explicitly approving the previous milestone.

If the repository already contains work from a milestone, the agent must inspect, validate, and extend it rather than overwrite it.

## Prompt 3: Reference Scoring

```text
Milestones 0 through 2 have been approved. Implement only Milestone 3: Reference Scoring.

Read AGENTS.md, GAME_SPEC.md, the implementation plan, ADR-001, ADR-002, ADR-006, ADR-007, ADR-008, and all referenced decisions. Inspect existing board and tile APIs before changing code.

Implement pure scene-independent reference logic for:

1. PokerHandEvaluator
   - five contiguous horizontal or vertical cells;
   - Pair, Two Pair, Three-of-a-Kind, Full House, Four-of-a-Kind, and Five-of-a-Kind;
   - configurable accepted point values;
   - canonical hand IDs;
   - one-time scoring of each window.

2. EdgeMatchScorer
   - compare visible rotated touching edges;
   - award +1 for each new matching boundary;
   - canonical boundary IDs;
   - evaluate each boundary once.

3. EdgeClusterScorer
   - color-specific connected components;
   - unique-tile component size;
   - separate components for different colors;
   - +3 for every completed four-tile milestone;
   - entitlement-delta logic for growth and merges;
   - reference flood-fill implementation.

4. Scoring architecture
   - immutable ScoreEvent types;
   - append-only ScoreLedger;
   - deterministic event IDs and ordering;
   - preview ScoreTransaction generation;
   - no mutation during preview;
   - non-negative integer points only;
   - no multipliers.

5. Verification
   - full static board audit;
   - ordered replay verifier;
   - comparison of incremental events, totals, hand IDs, boundaries, and cluster entitlements.

Add exhaustive unit tests for every accepted scoring rule, multiple simultaneous scoring events, one-time scoring, cluster merges, multiple colors, attribution, deterministic IDs, preview immutability, and randomized seeded incremental-versus-replay equivalence.

Do not implement UI effects, turn progression, AI, or optimized component caches. Correct reference logic comes first.

Run all checks and finish with the standard evidence report. Stop after Milestone 3.
```
